# Built-in Task Schedules plugin

OpenForge provides one-off and recurring task automation as a built-in trusted plugin, not as a core scheduler daemon or SDK capability. A Task Schedule belongs to a project, stores its state in project-scoped plugin storage, creates normal board Tasks with the `scheduled` label, and may request an Implementation Run through `tasks.startImplementation`. The desktop composer provides recurring presets and custom five-field cron. Agent-facing backend commands let agents create one-off schedules from exact RFC 3339 timestamps or recurring schedules from cron, list schedules, update active schedules, and cancel schedules without deleting their records.

This keeps scheduling aligned with the plugin platform while preserving OpenForge's focus model. Scheduled work does not introduce a separate automation inbox, auto-archive behavior, or scheduler-specific notifications. Schedules run only while OpenForge is open. Recurring schedules collapse missed fires into one catch-up fire on restart and skip a fire while their previous scheduled Task remains open. One-off schedules run once when due, including one catch-up run after restart, then remain visible as completed records. Agent commands use host-resolved Project context and require an explicit prompt; they do not copy, link, or add dependencies to the invoking Task. The plugin keeps the last five outcomes for diagnosis and remains the owner of scheduling until multiple plugins prove that OpenForge needs a shared scheduling capability.
