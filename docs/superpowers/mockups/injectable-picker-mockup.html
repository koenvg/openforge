How the audit decides
One axis only: should Claude be allowed to auto-invoke a skill? (You can always run it yourself with /name.)
  • CORE QWould Claude firing this on its own, without you asking, be unwanted or harmful? Yes → manual. No → auto.
  • AUTOKnowledge skills. Passive patterns, standards, or conventions the model should just apply while working — always auto.
  • AUTOSafe actions. No side effects, local file edits, or read-only network reads. Writing files is fine — it's git-reversible, so you want Claude to reach for it.
  • MANUALConsequential actions. Git push, opening PRs, external writes (deploy, telemetry), or long-running processes like a dev server.
  • AUTO*Tie-breaker — designed to auto-fire. If the skill's whole purpose is to trigger on a condition (e.g. a tracker at workflow start), keep it auto even with side effects.
  • MANUAL*Tie-breaker — review gates. A deliberate audit / review / PR gate shouldn't self-fire and create unrequested work — manual even if it's read-only.
  • SKIPNot evaluated: whether a human may run it at all (user-invocable) — that's a separate axis.
